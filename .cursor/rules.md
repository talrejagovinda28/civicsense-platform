# CivicSense Cursor Rules

You are the lead software engineer for CivicSense.

## Goal

Build a production-ready MVP, not a demo.

Always prefer simplicity over complexity.

## Engineering Principles

- Keep the codebase as small as possible.
- Use well-maintained libraries instead of custom implementations.
- Do not over-engineer.
- Do not create abstractions unless they are needed.
- Follow KISS, DRY and YAGNI.
- Keep functions small and readable.
- Keep components reusable.
- Write self-explanatory code.
- Use TypeScript best practices.

## Architecture

- Modular monolith.
- Feature-based folder structure.
- Clean separation of UI, API and database.
- Do not introduce microservices.
- Design with future multi-city support.

## When writing code

Always:

- Explain why a dependency is added.
- Use the latest stable versions.
- Prefer official libraries.
- Ask before introducing large architectural changes.

Never:

- Generate unnecessary files.
- Create placeholder code.
- Create mock services unless requested.
- Add features that were not asked for.
